# 한국어 레이어

한글 페이지에서 원본 규칙 위에 얹는 레이어. 근거 표시는 [검증](1차 자료 확인), [관행](실무 관행), [판단](이 레이어의 편집 판단)이다. 법과 브라우저 지원은 2026-11-03 기준이므로 배포 전에 다시 확인한다.

## 1. 언제 읽나

페이지 문구가 한글이거나 `<html lang="ko">`일 때 읽는다. 원본의 Floor와 게이트는 그대로 적용되고 이 파일은 한글 규칙을 더한다. 테마별 한글 글꼴은 `references/themes/hangul.json`에 있다. 영어 페이지는 읽지 않는다.

## 2. 글꼴

딜된 테마의 한글 글꼴을 `hangul.json`에서 읽어 라틴 글꼴 바로 뒤에 둔다. 한국 테마 셋(hanji, ganpan, gyeoljae)은 한글 짝을 각자의 `.md`에 담고 있으므로 `hangul.json`은 나머지 50개 테마에만 읽는다.

```css
--font-body: "<테마의 라틴 글꼴>", "Wanted Sans Variable", sans-serif;
```

브라우저는 글자마다 스택 앞에서부터 그 글리프를 가진 글꼴을 고른다. 라틴이 앞에 있어야 라틴은 테마의 성격을 지키고 한글만 고른 글꼴로 나온다. 한글 글꼴을 앞에 두면 라틴까지 그 글꼴로 바뀐다. 글꼴은 토큰으로만 선언하고 (48), 한글에 닿는 스택은 한글 글꼴 이름을 하나 이상 담는다 (92).

**x-height 균형.** 한글 글꼴의 x-height는 글꼴마다 다르다(본문 고딕 0.46~0.59em, Paperlogy 0.59, Do Hyeon 0.64, Maru Buri 0.47) [측정]. 라틴과 격차가 크면 한쪽이 작아 보인다. 자체 호스팅이면 `@font-face`의 `size-adjust`로 맞추고, CDN CSS는 고칠 수 없으므로 굵기를 한 단계 조정해 실제 헤드라인에서 눈으로 본다.

**기본값으로 쓰지 않는다.** Noto Sans KR, Nanum Gothic, 맑은 고딕(Malgun Gothic), Apple SD Gothic Neo, 돋움, 굴림, 바탕, 궁서, 그리고 한글에 `sans-serif`만 적는 것. 모델이 가장 먼저 고르는 글꼴이라 고른 것처럼 읽히지 않는다. KRDS(범정부 UI/UX 디자인 시스템)는 Noto Sans, Nanum Gothic을 대안으로 허용하지만 여기서는 디자인 이유로 막는다. 사용자 요청이나 프로젝트에 이미 있으면 쓰고 스탬프에 밝힌다.

**포화 글꼴(Picks에 근거).** Pretendard(jsDelivr 월 310억 건, 라틴이 Inter 계열이라 Inter 느낌의 테마와 겹친다), Spoqa Han Sans Neo, 표제용 Noto Serif KR. jsDelivr 월간 조회와 Google 인기 순위로 본 판단이다 [판단].

**한글은 고정폭 글꼴로 쓰지 않는다.** 고정폭은 숫자와 코드에만 쓴다.

## 3. 불러오기와 무게

- 한글 글꼴은 크다. Google의 한글 CSS는 `unicode-range` 조각으로 나뉘어 있고, CDN은 위의 조각 CSS를 쓴다. 자체 호스팅은 부분 집합이나 `unicode-range`로 나눈다.
- 쓰는 굵기만 부른다. KRDS의 이상적 구성은 400, 500, 700이고 굵기가 많으면 위계가 흐려진다 [검증].
- `font-synthesis: none`을 `html`에 둔다. 한글 글꼴은 대개 굵은체와 기울임꼴이 없고, 브라우저가 합성하면 가독성이 떨어지거나 뜻이 바뀔 수 있다(MDN `font-synthesis`) [검증]. Chrome 97, Safari 9, Firefox 34 이상.
- 호스트가 Google Fonts만 허용하면(일부 artifact 호스트) 목록의 Google 글꼴을 쓴다.

## 4. 조판

```css
:lang(ko) { word-break: keep-all; overflow-wrap: break-word; font-synthesis: none; }
:lang(ko) :is(h1, h2, h3) { text-wrap: balance; }
:lang(ko) p { text-wrap: pretty; }
```

**`keep-all` (93).** 한국어는 음절 사이가 아니라 어절 사이에서 줄을 바꾼다(CSS Text 4) [검증]. Chrome 130, 190px 상자의 직접 측정에서 기본값은 어절 안에서 끊었고("페/이지"), `keep-all`은 공백에서 끊었으며, `balance`만으로는 여전히 어절 안에서 끊겼다("소/개"). `overflow-wrap`은 긴 URL의 안전망이고, 줄어들어야 하는 flex·grid 항목은 `anywhere`다. `text-wrap: pretty`는 Firefox 미지원이라 점진적 향상이다.

**`text-autospace`는 쓰지 않는다.** 이 속성의 대상은 가나, 한자, 한의 부수이고 한글은 아니다(CSS Text 4) [검증].  `line-break`는 `auto`에 둔다(한글 효과가 문서에 없다).

**글자 수.** 한 줄 30~45자는 편집 관행이다 [관행]. 확인한 연구는 2003년 한 편(18명)이고 50자가 가장 빨랐다고 하나 초록은 직접 읽지 못했다. 한글 한 자는 1em 안팎이므로 `max-width: 38em`처럼 em으로 쓴다. 숫자 `0`은 한글보다 좁아 같은 줄을 `ch`로 쓰면 값이 커지고 게이트 25는 `ch` 값을 45~75ch로 본다. `ch`를 쓰면 고른 글꼴로 한 줄의 글자 수를 세어 본다.

**크기와 행간.** 본문 16px 이상이고, KRDS는 작아 보이는 Pretendard GOV에 17px을 쓴다 [검증]. 행간은 본문 1.5 이상이다. KRDS가 "최소 150%"를 요구하고 [검증], 실무 칼럼은 1.6을 권한다 [관행]. 1.8을 뒷받침하는 자료는 없다. 표제는 1.25~1.5를 권한다 [판단]. 게이트 95의 1.15는 린트 하한일 뿐 권장값이 아니다 (95).

**자간.** 기본값 0. KRDS는 본문과 중간 이하 표제에 0, 큰 표제(32px 이상)에만 +1px를 쓴다 [검증]. 한국 웹이 표제를 조인다는 검증된 근거는 찾지 못했다. 음수 자간은 직접 보고 정한 국소적 선택으로만 쓰고 큰 표제에서 -0.03em보다 좁히지 않는다. 작은 한글 라벨에는 양수 자간을 주지 않는다 (67).

**기울임꼴 없음 (94).** 한글 글꼴에는 기울임꼴이 없고 합성하면 가독성이 떨어진다. 강조는 굵기나 색으로 한다. 근거는 MDN `font-synthesis`이고 W3C KLReq에는 이 항목이 비어 있다 [검증]. 라틴 기울임은 원본 38i, 38ii를 따른다.

## 5. 문장 부호와 숫자

- 따옴표는 “ ”, ‘ ’를 쓴다. 낫표 「 」와 화살괄호는 2015년 개정 이후 따옴표로 바꿔 써도 된다 [검증]. 줄임표는 `…`, `……`, `...`가 모두 허용되고 앞말에 붙인다.
- **가운뎃점 `·`**은 같은 자격의 낱말을 묶는 정서법상의 부호다(「충북·충남」) [검증]. 구절 안에서는 맞는 표기다. 하지만 `A · B · C`로 메타 정보를 이은 줄은 원본의 템플릿 문장 부호라 금지다 (63). 원본 스크립트는 점 두 개부터 잡으므로 한 구절 안에는 하나까지만 두고 셋 이상은 쉼표로 쓴다(2015년 개정이 쉼표 대체 범위를 넓혔다) [검증].
- **날짜.** `2026. 11. 3.`처럼 쓰고 일 뒤 마침표를 빼지 않으며 연 뒤에 한 칸을 띈다. 범위는 `2026. 5.~10.` [검증, 국립국어원]. 풀어 쓰면 `2026년 11월 3일 (화)`, 시각은 `오후 3시 30분`이나 `15:30` [관행].
- **단위와 금액.** 단위 명사는 띄어 쓰되 숫자와 어울리면 붙여 쓸 수 있다(`35 그램`이 원칙, `35그램` 허용). 수는 만 단위로 띄어 쓴다(`1만 2000원`) [검증, 한글 맞춤법 제43항, 제44항]. 한 페이지에서 `12,000원`이나 `₩12,000` 하나로 통일한다 [관행]. `1만 2천 원`은 제44항의 예에 없어 쓰지 않는다.
- 전화번호는 `010-1234-5678`, `02-123-4567`, `tel:` 링크에는 숫자만 둔다 [관행]. 조사는 로마자 뒤에도 붙인다(`AI를`). 표의 숫자는 `tabular-nums`.

## 6. 문체와 한국어 슬롭

한 페이지에는 한 가지 어체만 쓴다. 고객 문구는 합쇼체(「~합니다」)와 해요체 중 하나로 정하고 라벨과 버튼은 명사형으로 쓴다 [관행].

게이트 96이 잡는 문구(짧고 정밀한 목록, 앱 범위에서는 건너뜀) (96).

- **광고 상투구** [판단]. 「지금 바로 시작하세요」, 「특별한 경험을 선사」, 「새로운 차원의」, 「당신의 일상을 바꿀」, 「혁신적인 솔루션」, 「완벽한 솔루션」, 「원스톱 토탈 솔루션」, 「새로운 기준을 제시」, 「그 이상의 가치」, 「최고의 서비스를 제공」. 목록으로 다룬 한국어 자료는 찾지 못했다.
- **AI 말투** [검증, 공개 분류와 칼럼]. 「결론적으로」, 「시사하는 바가 크」, 「되어진다」·「되어집니다」, 「크게 세 가지로 나눌 수」, 「지금이 바로 … 할 때입니다」, 「단순한 … 을 넘어」, 「도움이 되셨길 바랍니다」, 「잠시 떠올려 보세요」, 문장 첫머리의 「물론이죠」, 「에 있어서」(법령과 약관은 예외), 「논의를 진행하고자」, 「핵심적인 요소라고 볼 수 있」.

린트가 잡지 않고 판단할 표현. 「혁신적인」 단독, 「~의 모든 것」, 한 문단에 세 번 넘는 「~를 통해」·「~에 대해」(사람도 쓰므로 밀도만 본다), 「당신」(번역투로 읽힌다), 「차별화된」·「프리미엄」, 직역 CTA, 느낌표 연발, 이모지 글머리표.

「최고」, 「1위」, 「유일」, 「100%」는 표시광고법 제3조①(거짓·과장·기만 광고 금지)에 걸릴 수 있다. 출처와 날짜를 달거나 낮춘다(심사지침 본문은 미확인).

대신 쓰는 것은 사용자가 준 구체적인 명사와 숫자, 행동과 결과가 보이는 CTA(「견적 받기」)다. 숫자는 지어내지 않는다 (46a).

## 7. 한국 웹의 해부

- **모바일을 먼저 설계한다**(360~390px, 모바일 비중은 수치를 확인하지 못했다). 전화는 `tel:` 링크, 주소는 복사와 지도 버튼 [관행].
- **상거래 푸터.** 사이버몰에서 전자상거래를 하는 곳은 전자상거래법 제10조①과 시행규칙 제7조에 따라 초기 화면에 표시한다. 상호, 대표자 성명, 영업소 주소(불만 처리 주소가 다르면 함께), 전화번호, 전자우편주소, 사업자등록번호, 이용약관(연결 화면 가능), 호스팅서비스 제공자 상호(시행령 제11조의4), 공정거래위원회 사업자정보 공개페이지 연결 [검증, 시행 2026-07-21]. 청약을 받는 광고에는 통신판매업 신고번호와 신고기관(제13조①)이 더해진다. 판매하지 않는 포트폴리오나 브랜드 소개는 조문 문언상 해당하지 않는 것으로 읽히나 법률 판단은 아니다.
- 값은 전부 자료 요청의 빈칸이고 지어내지 않는다 (46a). 신고번호 칸에는 면제 또는 미신고 사유 자리를 둔다(면제 고시의 현행 문구는 미확인). 공정위 확인 페이지 주소도 미확인이라 적지 않는다. 판정은 `gates.md` § 5의 한국어 조항에서 한다.
- **개인정보처리방침** 링크는 문의 양식, 뉴스레터, 로그인, 주문 양식이 있는 페이지의 푸터에 둔다(개인정보 보호법 제30조, 시행 2026-09-11) [검증]. 보호책임자(성명 또는 부서와 연락처)도 방침에 들어간다. 방침 본문은 법률 문서라 쓰지 않고 링크 칸과 항목 점검표만 만든다.
- 푸터는 작은 글씨 2~4줄을 줄바꿈으로 나누고 처리방침 링크를 굵게 두는 것이 통례다 [관행]. 점으로 잇지 않는다 (63).
- **지도와 상담.** 카카오맵 링크는 `https://map.kakao.com/link/map/{이름},{위도},{경도}`가 공식 형식이다 [검증]. 네이버 지도는 사용자가 공유 버튼으로 복사한 장소 주소를 받고, 주소를 만들어 쓰지 않는다. 임베드는 키가 필요하니 링크로 건다. 카카오톡 채널은 `https://pf.kakao.com/_{채널 ID}/chat` 형식이고 채널 ID는 빈칸이다 [검증]. 결제 수단 표시는 실제로 받을 때만 둔다.
- **긴 이미지형 상세페이지는 한국 웹의 슬롭이다.** 글은 HTML 텍스트로 둔다 [판단].

## 8. 스탬프와 Picks

한국 테마 셋은 짝이 `.md`에 있으므로 거기서 읽는다. 스탬프 첫 줄 끝에 `· ko: <표제 한글 글꼴> / <본문 한글 글꼴>`을 붙이고, Picks에 한 줄을 더한다. `<html lang="ko">`를 선언한다 (91).

예. `- **Hangul** · Maru Buri 표제, Wanted Sans Variable 본문, 라틴은 테마 글꼴 그대로`. 포화 글꼴이면 근거를 덧붙인다.
